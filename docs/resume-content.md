# رزومه را چطور به‌روز کنم؟

سه فایل رزومه همان منبع اصلی پروژه‌اند. متن انگلیسی را در فیلد اصلی می‌نویسم و فارسی را کنار همان متن، داخل بخش ترجمه می‌گذارم. این‌طوری تاریخ، لینک و شناسه را فقط یک بار عوض می‌کنم.

برای نمونه، یک پروژه این شکلی می‌شود:

<div dir="ltr" align="left">

```json
{
  "id": "new-project",
  "title": "New Project",
  "description": "A mobile application for managing daily tasks.",
  "type": "mobile",
  "technologies": ["React Native", "TypeScript"],
  "translations": {
    "fa": {
      "title": "پروژهٔ جدید",
      "description": "اپلیکیشن موبایل برای مدیریت کارهای روزانه."
    }
  }
}
```

</div>

این فقط نمونهٔ ساختار است؛ اطلاعات واقعی پروژه را خودم وارد می‌کنم. با اضافه شدن همین رکورد به فایل رزومه، پروژه در پورتفولیو، پیش‌نمایش رزومه و PDF دیده می‌شود. در نسخهٔ آنلاین، تغییر بعد از بیلد و دیپلوی منتشر می‌شود.

لینک‌های هر پروژه داخل `links` قرار می‌گیرن: `website` برای سایت، `github` برای کد، `appStore` برای اپ استور، `googlePlay` برای گوگل پلی و `cafeBazaar` برای بازار. لینک در هر دو زبان مشترکه و هم روی کارت پروژه و هم در رزومه نمایش داده می‌شه. اگر لینک یا اطلاعات فناوری ندارم، چیزی از خودم اضافه نمی‌کنم.

در هر تجربه، نام شرکت، عنوان شغلی، محل همکاری و همهٔ دستاوردها ترجمه می‌شوند. تعداد دستاوردهای فارسی و انگلیسی باید برابر باشد؛ اگر یک دستاورد جدید اضافه کنم، ترجمه‌اش را هم اضافه می‌کنم. شناسه، تاریخ شروع و پایان و لینک‌ها داخل ترجمه نمی‌آیند. نام فناوری‌هایی مثل React و TypeScript مشترک است.

اگر یک رکورد تازه هنوز ترجمه نشده باشد، متن انگلیسی خودش با جهت درست نشان داده می‌شود. اطلاعات پایه هم همین ساختار ترجمه را دارد: نام، عنوان، معرفی و شهر. گروه مهارت فقط نام گروه را ترجمه می‌کند؛ کلیدواژه‌های فنی مشترک‌اند. برای تحصیلات، نام دانشگاه، رشته و مقطع ترجمه می‌شوند.

در صفحهٔ فارسی، رزومه و PDF فارسی‌اند؛ در صفحهٔ انگلیسی، انگلیسی. دکمهٔ زبان بالای رزومه همان نسخه را به زبان دیگر باز می‌کند. تاریخ‌ها میلادی می‌مانند؛ فقط ارقام و نام ماه در نسخهٔ فارسی فارسی می‌شوند.

قبل از پوش، تست، بررسی تایپ و بیلد را اجرا می‌کنم:

<div dir="ltr" align="left">

```bash
npm test
npm run typecheck
npm run build
```

</div>

فول‌استک فعلاً اطلاعات تماس دارد. ساختار دو‌زبانه برایش آماده است؛ سابقه و مهارت‌های واقعی را بعداً به همان فایل اضافه می‌کنم.

## اطلاعات درخواست همکاری

سطح زبان‌ها در آرایهٔ اختیاری `languages` قرار می‌گیره. هر مورد `language` و `fluency` داره و ترجمهٔ فارسی‌ش داخل `translations.fa` می‌آد. سطح انگلیسی فعلاً B1 و در حال یادگیریه؛ ترکی متوسطه. سطح‌ها خوداظهاری‌اند و نباید از خودم براشون مدرک یا سطح بالاتر بنویسم.

لینک سایت از `basics.portfolio` و شرایط همکاری از `basics.availability` وارد پیش‌نمایش و PDF می‌شه. متن فارسی شرایط همکاری هم داخل `basics.translations.fa.availability` قرار می‌گیره. آماده بودن برای جابه‌جایی به معنی داشتن اجازهٔ کار در کشور مقصد نیست.

اگر پروژه‌ای فقط برای نمایش در سایت مناسبه، `includeInResume` رو `false` می‌ذارم. پروژه همچنان توی پورتفولیو می‌مونه؛ فقط از پیش‌نمایش و PDF رزومه کنار می‌ره. اگر این فیلد رو ننویسم، پروژهٔ جدید به شکل پیش‌فرض وارد هر دو خروجی می‌شه.

نسخهٔ درخواست همکاری باید کوتاه، خوانا و مرتبط با موقعیت شغلی باشه. درصدهای عملکرد رو فقط وقتی اضافه می‌کنم که معیار، روش اندازه‌گیری و مثال قبل و بعدش معلوم باشه. امتیاز صد یا نتیجهٔ استخدام با تغییر قالب تضمین نمی‌شه.

قالب PDF برای یک صفحهٔ خوانا تنظیم شده؛ نسخه‌های فعلی ریکت و ریکت نیتیو با همین محتوا یک‌صفحه‌اند. متن پنهان یا قطع نمی‌شه و اندازهٔ فونت هم خودکار ریز نمی‌شه. اگر بعداً سابقه یا پروژهٔ بیشتری اضافه کنم و جا نباشه، خروجی خودش به صفحهٔ بعد ادامه پیدا می‌کنه. محل فعلی از اطلاعات پایه می‌آد و روی محل همکاری‌های قبلی تأثیری نداره.

برای جا دادن پروژه‌ها، هیچ پروژه‌ای را خودکار از رزومه حذف نمی‌کنم. وقتی تعداد پروژه‌های رزومه بیشتر از سه مورد باشد، فهرست به شکل فشردهٔ نام و لینک نمایش داده می‌شود؛ پروژهٔ بدون لینک همچنان با توضیحش می‌آید. جزئیات کامل پروژه‌ها در دادهٔ اصلی و پورتفولیو می‌مانند. هر پنج پروژهٔ وب و هر شش پروژهٔ موبایل فعلاً در رزومه‌های ریکت و ریکت نیتیو فعال‌اند.
