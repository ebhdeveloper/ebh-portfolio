# پورتفولیوی ابراهیم حمیدی

این پروژه برای پورتفولیو و رزومه‌مه. می‌خوام اطلاعاتم رو توی سه فایل جدا نگه دارم و سایت و نسخه‌های پی‌دی‌اف از همون فایل‌ها ساخته بشن؛ یکی برای ریکت، یکی برای ریکت نیتیو و یکی برای فول‌استک.

نسخه اول صفحه پورتفولیو آماده‌ست: معرفی، پروژه‌ها با فیلتر وب و موبایل، تجربه‌ها و تماس. رابط کاربری فارسی و انگلیسی، فونت‌ها و تم روشن و تاریک هم وصلن. خروجی پی‌دی‌اف و ترجمه متن خود رزومه مرحله‌های بعدی‌ان.

## اجرا روی سیستم خودم

پروژه با نود نسخه ۲۲٫۲۳٫۱ تنظیم شده. برای نصب پکیج‌ها و بالا آوردن محیط توسعه، این دستورها رو توی پوشه پروژه می‌زنم:

<div dir="ltr" align="left">

```bash
npm ci
npm run dev
```

</div>

بعد این آدرس رو توی مرورگر باز می‌کنم:

<div dir="ltr" align="left">

```text
http://localhost:3000
```

</div>

## تنظیمات تیلویند

تیلویند نسخه چهار از اول توی پروژه نصب بود و با لودر توربوپک به نکست وصله. تنظیمات مشترک استایل‌ها رو اینجا نگه می‌دارم:

<div dir="ltr" align="left">

```text
src/styles/theme.css
```

</div>

رنگ پس‌زمینه، رنگ متن و فونت‌ها از همین فایل میان. گردی کارت‌ها فعلاً بیست پیکسل و حداکثر عرض محتوای صفحه هفتاد و پنج رمه. این مقدارها رو بعداً با طراحی صفحه تنظیم می‌کنم.

با این تنظیمات، می‌تونم توی کامپوننت‌ها از این کلاس‌ها استفاده کنم:

<div dir="ltr" align="left">

```tsx
<section className="mx-auto max-w-page rounded-card bg-background p-6 font-sans text-foreground">
  ...
</section>
```

</div>

تو نسخه چهار، تنظیمات رو داخل استایل و با دستورهای زیر می‌نویسم:

<div dir="ltr" align="left">

```css
@theme { /* Shared design values */ }
@theme inline { /* Values linked to CSS variables */ }
```

</div>

فایل استایل اصلی، تیلویند و تنظیمات مشترک رو وارد می‌کنه. تم در اولین بازدید از تنظیم سیستم پیروی می‌کنه. با دکمه بالای صفحه می‌تونم تم رو عوض کنم و انتخابم برای بازدید بعدی ذخیره می‌شه.

## فونت‌ها و رنگ‌ها

فونت فارسی ایران‌سنس با اعداد فارسیه و برای انگلیسی از مونتسرات استفاده می‌کنم. هر چهار فایل داخل پروژه هستن و نکست اون‌ها رو از خود سایت بارگذاری می‌کنه.

<div dir="ltr" align="left">

```text
src/assets/fonts/
  iran-sans-regular.ttf
  iran-sans-bold.ttf
  montserrat-medium.ttf
  montserrat-bold.ttf

src/lib/fonts.ts
```

</div>

فونت انگلیسی وزن متوسط و بولد داره. فارسی هم فایل معمولی با وزن ۴۰۰ و فایل بولد با وزن ۷۰۰ داره؛ متن‌های ضخیم از خود فایل بولد استفاده می‌کنن.

برای مشخص کردن زبان و فونت یک بخش، این شکلی می‌نویسم:

<div dir="ltr" align="left">

```tsx
<p lang="fa" dir="rtl" className="font-fa font-normal">
  متن فارسی معمولی
</p>
<p lang="fa" dir="rtl" className="font-fa font-bold">
  متن فارسی بولد
</p>
<p lang="en" dir="ltr" className="font-en font-medium">
  English text
</p>
<p lang="en" dir="ltr" className="font-en font-bold">
  English heading
</p>
```

</div>

فونت با زبان صفحه انتخاب می‌شه؛ ایران‌سنس برای فارسی و مونتسرات برای انگلیسی. بخش انگلیسی داخل صفحه فارسی هم زبان و جهت خودش رو داره. نمایش کدها از فونت ثابت‌عرض سیستم استفاده می‌کنه.

ظاهر فعلی سرمه‌ای و آبیه، با گرادیانت آبی و فیروزه‌ای، هدر و کارت‌های شیشه‌ای و حرکت آرام. تم روشن هم از آبی خیلی روشن استفاده می‌کنه. رنگ، گرادیانت و زمان حرکت اسم مشخص دارند تا مجبور نباشم مقدارها رو توی همه کامپوننت‌ها تکرار کنم:

<div dir="ltr" align="left">

```text
bg-background          → Page background
bg-surface             → Cards and controls
text-foreground        → Main text
text-muted-foreground  → Secondary text
border-border          → Borders
bg-accent              → Primary actions
text-accent-foreground → Text on primary actions
outline-ring           → Keyboard focus
```

</div>

برای عوض کردن تم، یک فراهم‌کننده تم توی لایه اصلی برنامه دارم. خود لایه اصلی همچنان کامپوننت سروره؛ فراهم‌کننده و دکمه تغییر تم روی مرورگر اجرا می‌شن. زبان از مسیر صفحه مشخص می‌شه و با دکمه هدر تغییر می‌کنه. هر زبان جهت متن و فونت خودش رو داره.

<div dir="ltr" align="left">

```text
/en
/fa
```

</div>

## سیستم طراحی

رنگ و فونت فقط شروع کارن. اندازه متن، فاصله کناره صفحه، فاصله بین بخش‌ها، گردی گوشه‌ها و حرکت دکمه‌ها هم مرجع مشترک دارن. دکمه اصلی و فرعی از یک استایل استفاده می‌کنن؛ دکمه تغییر تم هم به همین پایه وصله.

وقتی بخش‌های بعدی رو می‌سازم، اول همین قواعد و کامپوننت‌ها رو استفاده می‌کنم. توضیح کامل و مثال‌ها توی [راهنمای سیستم طراحی](docs/design-system.md) هست.

## معماری و بخش‌های صفحه

صفحه نکست فقط بخش‌های پورتفولیو رو کنار هم می‌گذاره. معرفی، پروژه‌ها، تجربه‌ها و تماس هر کدوم کامپوننت خودشون رو دارن. داده حرفه‌ای از رزومه می‌آد، ترجمه دکمه‌ها و عنوان‌ها جداست و استور فقط انتخاب فیلتر رو نگه می‌داره.

[راهنمای معماری](docs/architecture.md) توضیح می‌ده هر بخش کجا قرار می‌گیره، مسیرهای نکست چطور انتخاب شده‌اند و قابلیت‌های بعدی چطور اضافه می‌شن. آدرس ناموجود، صفحه ۴۰۴ همان زبان رو با لینک بازگشت به پورتفولیو نمایش می‌ده.

## فایل‌های رزومه

ساختار این بخش فعلاً این شکلیه:

<div dir="ltr" align="left">

```text
src/
  data/resumes/
    react.json
    react-native.json
    fullstack.json
  lib/resume/
    types.ts
    validate.ts
    load.ts
    validate.test.ts
    load.test.ts
    test-fixtures.ts
```

</div>

فایل اول برای رزومه وب، دومی برای رزومه موبایل و سومی برای فول‌استکه. رزومه فول‌استک فعلاً فقط اطلاعات پایه داره؛ تجربه‌هاش رو بعداً اضافه می‌کنم.

هر فایل پنج بخش داره:

<div dir="ltr" align="left">

```text
basics     → Personal information
work       → Work experience
projects   → Portfolio projects
skills     → Skills
education  → Education
```

</div>

تو بخش اطلاعات شخصی، اسم و ایمیل لازمه. تجربه‌ها، پروژه‌ها، مهارت‌ها و تحصیلات هم باید آرایه باشن؛ اگه هنوز چیزی براشون ندارم، آرایه رو خالی می‌ذارم.

## خوندن اطلاعات

برای گرفتن یک رزومه مشخص، از تابع انتخاب رزومه استفاده می‌کنم. تابع دوم هم تجربه‌ها و پروژه‌های هر سه فایل رو برای پورتفولیو کنار هم می‌ذاره:

<div dir="ltr" align="left">

```ts
import { buildPortfolio, getResume } from "@/lib/resume/load";

const resume = getResume("react-native");
const portfolio = buildPortfolio();
```

</div>

صفحه سایت الان از همین تابع‌ها نام، اطلاعات تماس، پروژه‌ها و تجربه‌ها رو می‌گیره. تجربه‌های ترکیب‌شده برای نمایش از جدید به قدیم مرتب می‌شن، بدون تغییر ترتیب داخل فایل‌های اصلی. سازنده پی‌دی‌اف هم در مرحله بعد از همین داده اعتبارسنجی‌شده استفاده می‌کنه.

فایل‌های رزومه مستقیم وارد برنامه می‌شن. توی محیط توسعه، بعد از ذخیره فایل، مصرف‌کننده داده می‌تونه اطلاعات جدید رو بخونه. برای نسخه آنلاین هم باید تغییرات رو به گیت‌هاب بفرستم و انتشار جدید ورسل موفق بشه.

## اضافه کردن تجربه کاری

هر تجربه و نمونه‌کار یه شناسه ثابت داره. اگه عنوان یا توضیح رو عوض کردم، شناسه رو عوض نمی‌کنم. برای دو سمت متفاوت توی یک شرکت هم دو شناسه جدا می‌ذارم.

شناسه توی یک آرایه از یک فایل نباید تکراری باشه، ولی یک تجربه یا پروژه مشترک می‌تونه توی چند رزومه با همون شناسه بیاد. شناسه تجربه‌ها و پروژه‌ها هم جدا از هم بررسی می‌شن.

برای اضافه کردن تجربه، یه مورد شبیه این رو به آرایه تجربه‌های کاری اضافه می‌کنم:

<div dir="ltr" align="left">

```json
{
  "id": "new-company-mobile",
  "company": "New company",
  "position": "React Native Engineer",
  "location": "Remote",
  "startDate": "2026-10",
  "highlights": ["Describe your actual contribution."]
}
```

</div>

تاریخ رو به شکل سال و ماه می‌نویسم. اگه فقط سال رو می‌دونم، همون سال کافیه؛ ماه حدسی اضافه نمی‌کنم:

<div dir="ltr" align="left">

```text
2026-10
2026
```

</div>

برای شغلی که هنوز توش کار می‌کنم، تاریخ پایان رو نمی‌ذارم. تاریخ پایان نباید قطعاً قبل از شروع باشه؛ تاریخ بدون ماه، بازه همون سال حساب می‌شه. مکان دو تجربه توی رزومه ریکت هم مشخص نبود؛ فعلاً همین رو نوشتم.

## تجربه‌ها و پروژه‌های مشترک

توی فهرست مشترک سایت، اول رزومه ریکت خونده می‌شه، بعد ریکت نیتیو و بعد فول‌استک. اگه یک شناسه توی چند فایل باشه، اولین مورد کامل استفاده می‌شه؛ متن نسخه‌ها با هم قاطی نمی‌شه و ترتیب فایل‌ها هم حفظ می‌شه.

مثلاً اگه یک تجربه توی هر دو رزومه وب و موبایل باشه، نسخه وب توی فهرست مشترک میاد. تغییر متن نسخه موبایل، متن فهرست مشترک رو عوض نمی‌کنه. البته رزومه موبایل همچنان متن مخصوص خودش رو داره.

## اضافه کردن نمونه‌کار

نمونه‌کار جدید رو به آرایه پروژه‌ها اضافه می‌کنم:

<div dir="ltr" align="left">

```json
{
  "id": "new-mobile-app",
  "title": "New mobile app",
  "description": "Describe the product and your contribution.",
  "type": "mobile",
  "technologies": ["React Native", "TypeScript"],
  "image": "/images/projects/new-mobile-app.png",
  "links": { "website": "https://example.com/" }
}
```

</div>

نوع پروژه یکی از این سه حالته: وب، موبایل یا هر دو. مقدار انگلیسی‌شون توی فایل اینه:

<div dir="ltr" align="left">

```text
web
mobile
both
```

</div>

تصویر و لینک اختیاری‌ان؛ اگه هنوز آماده نیستن، اون دو بخش رو حذف می‌کنم. فایل تصویر مثال بالا باید اینجا باشه:

<div dir="ltr" align="left">

```text
public/images/projects/new-mobile-app.png
```

</div>

مسیر تصویر توی داده باید از پوشه تصاویر شروع بشه، به پوشه بالاتر نره و پارامتر آدرس یا کاراکتر کدگذاری‌شده نداشته باشه:

<div dir="ltr" align="left">

```text
/images/
```

</div>

فعلاً فقط شکل مسیر بررسی می‌شه، نه اینکه فایل تصویر واقعاً وجود داشته باشه.

برای لینک‌ها، این چهار کلید رو دارم:

<div dir="ltr" align="left">

```text
website
github
appStore
googlePlay
```

</div>

آدرس‌ها باید با یکی از این دو پروتکل باشن:

<div dir="ltr" align="left">

```text
https://
http://
```

</div>

لیست تکنولوژی‌ها هم می‌تونه خالی باشه. مثلاً برای واندر فروت فعلاً فقط همکاری‌ام به‌عنوان توسعه‌دهنده ثبت شده؛ تکنولوژی‌ای که مطمئن نیستم رو ننوشتم.

## تست‌ها

برای بررسی پروژه این دستورها رو دارم:

<div dir="ltr" align="left">

```bash
npm test
npm run test:watch
npm run typecheck
npm run lint
```

</div>

تست‌ها بررسی می‌کنن که داده‌ها معتبر باشن، رزومه درست انتخاب بشه، موارد تکراری درست کنار برن و با اضافه شدن تجربه یا پروژه، خروجی داده هم تغییر کنه. انتخاب پلتفرم، مستقل بودن استورها، ترتیب تجربه‌ها و نمایش فقط لینک‌های پشتیبانی‌شده هم بررسی می‌شن. خود فایل‌های رزومه هم تست می‌شن.

دستور دوم تست‌ها رو در حالت توسعه اجرا می‌کنه تا بعد از تغییر فایل‌ها دوباره بررسی بشن. دستور سوم اول تایپ‌های نکست رو می‌سازه و بعد تایپ‌اسکریپت رو بررسی می‌کنه:

<div dir="ltr" align="left">

```bash
next typegen && tsc --noEmit --incremental false
```

</div>

این مرحله لازمه چون توی محیط تازه گیت‌هاب، تایپ‌های تولیدشده هنوز وجود ندارن. فایل‌های تولیدشده رو هم وارد گیت نمی‌کنم.

تست مرورگر و خروجی پی‌دی‌اف رو وقتی اون بخش‌ها ساخته بشن اضافه می‌کنم.

## گیت‌هاب و ورسل

بعد از ارسال تغییرات یا باز کردن و به‌روزرسانی درخواست ادغام، گیت‌هاب اکشن این دستورها رو به‌ترتیب اجرا می‌کنه:

<div dir="ltr" align="left">

```bash
npm ci
npm test
npm run typecheck
npm run lint
npm run build
```

</div>

نسخه آنلاین سایت روی ورسل منتشر می‌شه. فعلاً تست‌های گیت‌هاب و انتشار ورسل جدا از همن؛ شکست تست‌ها به‌تنهایی جلوی انتشار سایت رو نمی‌گیره.


## دیدن و دانلود رزومه

از منوی رزومه در هدر، نسخه ریکت، ریکت نیتیو یا فول‌استک رو انتخاب می‌کنم. هر نسخه صفحه خودش رو داره و از JSON همون نسخه ساخته می‌شه. دانلود PDF فایل رو مستقیم می‌گیره؛ دکمه چاپ هم پنجره چاپ مرورگر رو باز می‌کنه و از اونجا می‌شه Save as PDF رو انتخاب کرد.

فول‌استک فعلاً فقط اطلاعات تماس داره. هر وقت JSON رو کامل کنم و پروژه دوباره بیلد و دیپلوی بشه، پیش‌نمایش و PDF هر دو به‌روز می‌شن. فونت‌های خروجی همراه پروژه بسته‌بندی شده‌اند؛ تولید PDF به دانلود فونت از اینترنت وابسته نیست.

</div>
