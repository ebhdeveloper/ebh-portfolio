# معماری پورتفولیو

این پروژه یک پورتفولیوی قابل توسعه با دو زبان، دو تم و سه نسخه رزومه است. ساختار رو بر اساس قابلیت‌ها می‌چینیم تا تغییر یک بخش، تغییر همه سایت رو لازم نکنه.

## مرز بخش‌ها

<div dir="ltr" align="left">

```text
src/
  app/[locale]/        # Routes, layouts, metadata
  i18n/                # Language routing and request configuration
  messages/            # Persian and English interface copy
  features/portfolio/  # Portfolio sections, view models, project filters
  features/resume/     # Resume menu, preview, print and server PDF rendering
  components/ui/       # Reusable UI primitives
  components/providers/# Theme provider
  styles/              # Shared design tokens and component styles
  data/resumes/        # Three canonical resume JSON files
  lib/resume/          # Types, validation, loading and aggregation
```

</div>

صفحه نکست فقط بخش‌ها رو کنار هم می‌گذاره. اجزای پورتفولیو توی پوشه خودشون قرار می‌گیرن. کامپوننت عمومی درباره شرکت، پروژه یا فایل رزومه چیزی نمی‌دونه. بخش رزومه هم به رابط کاربری، زبان صفحه و زوستاند وابسته نیست.

## داده و ترجمه

اطلاعات حرفه‌ای فقط از سه فایل رزومه خوانده می‌شه و قبل از نمایش اعتبارسنجی می‌شه. ساختار فعلی ترکیب اطلاعات و حذف موارد تکراری رو حفظ می‌کنیم. افزودن پروژه به فایل رزومه، اون رو بعد از بیلد و دیپلوی بعدی وارد فهرست سایت می‌کنه؛ پنل مدیریت و نوشتن فایل در ورسل نداریم.

متن دکمه‌ها و عنوان بخش‌ها در دو فایل ترجمه قرار می‌گیرن. متن رزومه فعلی انگلیسیه و در صفحه فارسی هم با زبان و جهت درست نمایش داده می‌شه. برای ترجمه خود رزومه در آینده، ترجمه‌ها به شناسه پایدار هر تجربه و پروژه متصل می‌شن؛ اطلاعات اصلی رو در چند جای متفاوت کپی نمی‌کنیم.

## سرور و مرورگر

صفحه، هدر، معرفی، تجربه‌ها و تماس روی سرور رندر می‌شن. فقط تعامل‌های لازم مثل تغییر تم و فیلتر پروژه‌ها کد مرورگر دارند. داده رزومه رو داخل استور ذخیره نمی‌کنیم. استور فیلتر برای هر نمونه بخش پروژه ساخته می‌شه تا وضعیت بین درخواست‌های سرور مشترک نشه.

زبان با مسیر صفحه مشخص می‌شه؛ انگلیسی و فارسی مسیر جدا دارند. مسیر بدون زبان به زبان مناسب هدایت می‌شه. جهت صفحه و فونت با زبان تغییر می‌کنن. تم در اختیار فراهم‌کننده فعلی تم می‌مونه و با مدیریت وضعیت دوم دوباره پیاده نمی‌شه. تغییر زبان با لینک معمولی و بارگذاری کامل صفحه انجام می‌شه تا جهت، فونت و فراهم‌کننده تم در ریشه صفحه با هم تازه شوند؛ تم ذخیره‌شده هم حفظ می‌شه. این انتخاب جلوی برگشت تم قدیمی در صفحه‌های کش‌شده رو می‌گیره.

## تصمیم‌های مسیردهی

مقاله [Byte & Builders](https://byteandbuilders.com/blog/nextjs-15-app-router-best-practices) درباره پیش‌فرض بودن کامپوننت سرور، بارگذاری تدریجی، مسیر موازی و کش صحبت می‌کنه. نسخه پروژه ما نکست ۱۶.۴ است؛ قراردادها رو با مستندات همان نسخه داخل پکیج تطبیق می‌دیم.

مسیر اصلی از بخش زبان شروع می‌شه. لایوت زبان فقط فونت، جهت، فراهم‌کننده‌ها و متادیتای مشترک رو می‌سازه. صفحه پورتفولیو همچنان یک فایل کوچک برای کنار هم گذاشتن قابلیت‌هاست. فیلتر نمونه‌کارها و تغییر تم مرز کلاینت دارند؛ دریافت اطلاعات رزومه و بخش‌های دیگر روی سرور می‌مونن.

برای آدرس ناموجود، مسیر catch-all تابع `notFound` رو صدا می‌زنه تا همان لایوت زبان و صفحه ۴۰۴ ترجمه‌شده نمایش داده بشه. مسیر خاص آینده مثل پروژه یا رزومه از مسیر عمومی catch-all اولویت بالاتری خواهد داشت؛ آدرس ناموجود رو به صفحه اصلی با پاسخ موفق تبدیل نمی‌کنیم.

<div dir="ltr" align="left">

```text
app/[locale]/
  layout.tsx          # Shared locale document and providers
  page.tsx            # Current portfolio page
  not-found.tsx       # Translated 404 interface
  resume/[profile]/page.tsx # React, React Native and Fullstack previews
  [...rest]/page.tsx  # Unknown paths call notFound()
```

</div>

صفحه‌های آینده پروژه و رزومه را زیر همین زبان و با بخش قابلیت جدا می‌سازیم. گروه مسیر وقتی به لایوت‌های متفاوت برای سایت و خروجی چاپ نیاز داریم اضافه می‌شه. مسیر موازی برای بخش‌های مستقل و پیچیده‌ست؛ برای یک صفحه پورتفولیو نیازی بهش نداریم. داده JSON همین حالا در زمان بیلد در دسترس است؛ انتظار یا اسکلت بارگذاری ساختگی اضافه نمی‌کنیم. وقتی داده کند خارجی اضافه شد، همان بخش با `Suspense` بارگذاری می‌شه. تغییر فایل JSON فعلاً با بیلد و دیپلوی منتشر می‌شه؛ رفتار کش نکست ۱۵ را بدون بررسی به نکست ۱۶ منتقل نمی‌کنیم.

## سیستم طراحی

رنگ‌ها معنایی، اندازه‌ها مشترک و استایل‌های مخصوص هر بخش نزدیک همان بخش قرار می‌گیرن. دکمه عمومی، کارت پروژه و بخش معرفی از توکن‌های یکسان استفاده می‌کنن. حالت موبایل، کیبورد، کاهش حرکت و هر دو جهت متن در همین مرحله بررسی می‌شن.

## صفحه رزومه و خروجی PDF

هر پروفایل زیر مسیر زبان صفحهٔ خودش را دارد. صفحه از بارگذار اعتبارسنجی‌شده و مدل نمایش مشترک در بخش رزومه استفاده می‌کند؛ سابقه‌ها با تاریخ شروع مرتب می‌شوند و بخش خالی نمایش داده نمی‌شود. فایل Fullstack فعلاً فقط اطلاعات تماس دارد؛ توضیح این وضعیت بیرون برگهٔ رزومه است و وارد چاپ یا PDF نمی‌شود.

منوی رزومه یک کامپوننت کوچک کلاینت با باز و بسته شدن بومی مرورگر است. کلید Escape و کلیک بیرون آن را می‌بندند. عنوان‌ها و کنترل‌ها ترجمه می‌شوند؛ محتوای رزومه مطابق JSON انگلیسی است. داده داخل زوستاند کپی نمی‌شود.

دانلود مستقیم از مسیر `/api/resume/[profile]` انجام می‌شود. این مسیر یک Route Handler با اجرای Node دارد و PDF را با `@react-pdf/renderer` از همان مدل نمایش می‌سازد. فونت‌های محلی مونتسرات در فایل سرور ثبت و با تنظیم `outputFileTracingIncludes` همراه دیپلوی بسته‌بندی می‌شوند. کتابخانه PDF وارد بسته کلاینت نمی‌شود. پروفایل نامعتبر در API پاسخ ۴۰۴ می‌گیرد. فایل، پیوست با نام مشخص است و کش مرورگر برای آن غیرفعال است.

دکمهٔ چاپ بعد از آماده شدن فونت‌های صفحه پنجره چاپ مرورگر را باز می‌کند. استایل چاپ، کنترل‌های سایت را مخفی و برگه A4 روشن نمایش می‌دهد. ذخیره از پنجره چاپ با انتخاب Save as PDF انجام می‌شود؛ دکمه دانلود مستقیم به این پنجره وابسته نیست. محتوای PDF و پیش‌نمایش مشترک است، اما دو موتور صفحه‌بندی مستقل دارند.

تغییر فایل JSON با بیلد و دیپلوی بعدی وارد صفحه و PDF می‌شود. مسیر نامعتبر پیش‌نمایش رابط ۴۰۴ همان زبان و noindex دارد؛ در پاسخ‌هایی که پیش از خطا استریم شده‌اند، طبق رفتار نکست ممکن است وضعیت HTTP برابر ۲۰۰ باشد. خط‌تیره‌های تایپوگرافیک ناسازگار با فونت خروجی فقط در مدل نمایش به خط‌تیره معمولی تبدیل می‌شوند؛ منبع JSON تغییر نمی‌کند.

## بررسی و توسعه بعدی

تست‌های منطق داده، انتخاب پروژه و مستقل بودن استورها اجرا می‌شن. زبان‌ها، مسیر نامعتبر، تم، لینک‌ها و اندازه موبایل هم در بیلد و مرورگر بررسی می‌شن. برای ظاهر ساده، تستی که فقط کد کلاس‌ها رو تکرار کنه نمی‌نویسیم.

متادیتای هر زبان از همان زبان می‌آد. نام و لینک تماس از رزومه گرفته می‌شن. آمار ساختگی، تصویر جعلی از محصول و عنوان شغلی تأییدنشده اضافه نمی‌کنیم. نمایش حالت خالی برای فیلتر و تجربه‌ها بخشی از رفتار واقعی صفحه‌ست.

قابلیت‌های بعدی به ترتیب: تکمیل اطلاعات Fullstack، جزئیات پروژه‌ها و تصاویر واقعی، ترجمه محتوای رزومه، سپس بهبود اشتراک‌گذاری و تست مسیرهای مهم در مرورگر. احراز هویت، دیتابیس و پنل مدیریت تا وقتی نیاز واقعی نداریم اضافه نمی‌شن.
